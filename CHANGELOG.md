# Changelog

Hewn follows semver for the CLI and your data: `hewn upgrade` stays within a 0.x line, and a new line (0.4 → 0.5) is a deliberate move. The tool contract (the ABI, [`spec/`](spec/README.md#versions)) is versioned separately as `major.minor`: minor versions only add, and a tool declares the lowest one it needs.

## 0.4.10 (unreleased)

- **A build can pause.** A host's builder can stop a build part-way with its work kept (for example once it has used a build's allowance) and leave the choice to you: the build shows as paused, not failed, with the host's words, **Continue** (it carries on from where it stopped) and **Stop**, on its page, in the Inbox, in Activity and on the tool. Only you can continue it (agents see it paused and tell you). Until you choose, changes to that tool wait behind it, also ones asked for after it paused, and a new tool that's paused keeps its name: asking for it again says it's paused. See [When a build fails](docs/building-tools.md#when-a-build-fails).
- **A build's screen is checked on a phone too:** the visual check renders it 390 px wide as well as 1280, in light and dark, and an error only the phone shows fails the build (it says so: "on the phone (390 px): …"). A page no longer stalls the check: `alert()`, `confirm()` and `prompt()` are dismissed, and a page that stops responding fails it after 60 s. The check now also renders the whole page on both screens, the images a builder will be shown of its work, and can measure what to fix (what sticks out past the phone's edge, text cut short, buttons that break the page); the build-quality bench measures with the same code.
- **The intake writes a brief, not a spec.** For a new tool it now writes what it's for, what it keeps, what you decided, what it needs and how it should feel, and leaves the operations, tests and layout to the builder, which also reads your own words. On the build-quality bench's first builds (out of 60, one run per case over six cases) the brief scored 40.5, a one-line spec 39.8, the spec with UI intent 38.7 and the full spec 37.2; the brief's builds also had the owner's whole conversation and were judged against it, so that's a lead, not a like-for-like result. The proposal card shows what it keeps and what's decided instead of a list of operations (**Show brief** has the rest); a change, a connection and a tool drafted before this still list them. A schedule you approve with a tool or a change is named in what the builder reads, so it builds that operation. See [Asking for a tool](docs/building-tools.md#asking-for-a-tool).
- **The builder reads what you said, not only the spec.** A tool or change you asked for in the chat goes to the builder with your conversation with the intake, in your own words, oldest first, after the request: where the spec is silent, vague or differs, your words win, the latest where you changed your mind. Your instructions and Hewn's rules for tools still hold. A draft the intake showed you along the way comes down to its name and purpose (a change, to the first line of what it changes), and a long conversation to its first turn, your latest and the latest that fit, each turn cut at 4,000 characters. A build an agent asks for is unchanged. See [The build](docs/building-tools.md#the-build).
- **A tool's own CSS wins over the design system.** `ui.css` is now in the cascade layer `hewn`, so a tool's own rules always apply, whatever their selectors, except `ui.css`'s `!important` rules: `[hidden]` and reduced motion. Before, a tool's dark colours lost to the design system's own (its dark-mode rule was more specific), so a tool with its own palette looked like Hewn in dark mode. A token a tool sets in plain `:root` now applies in dark mode too, so give it a dark value as well; a tool that set only light colours may now keep them in dark mode, and **Ask builder to fix** sorts it. Hewn's own pages look the same as before. See [`ui.css` in the tool docs](spec/tools.md).
- **Tools follow Hewn's light or dark.** With Appearance set to Light or Dark (Settings › General, or `⌘K`), a tool open in Hewn now follows it from its first paint, as Hewn's own pages do, and switches with it; before, it followed the system's setting whatever Hewn showed. A screen built on Hewn's styles (`ui.css`) follows at once; a tool's own colours follow when written with `light-dark()`, and a tool that sets its own `data-theme` keeps it: see [Tool UIs](spec/tools.md#tool-uis).
- **A conversation waits for you.** Leave New (or a tool's **Change it**) in the middle and come back, with Back or New: it's where you left it in that browser tab, with what you'd typed and not sent, its last proposal still buildable; a reply that was on its way arrives there (or why it failed). It stays until you build from it or start a new one with **+ New** (it asks first). Opening **Change it**, **Ask builder to fix this** or **Ask builder** with its text in the box starts a new conversation, which replaces the kept one once it's sent. See [Asking for a tool](docs/building-tools.md#asking-for-a-tool).
- **Stop stops the intake.** Stop in the chat while it's answering ends the run (its CLI, or the host's) instead of letting it finish unseen.
- The intake no longer ends its questions with "Just say ok if that looks good." An "ok" still takes all its defaults.
- **Esc closes `⌘K`** at once, also with something typed (it used to clear the search first).
- For hosts: `BUILDER.md` in a build request's `files` now quotes the owner's conversation with the intake after the request (up to 40,000 characters) when the owner asked for the build in the chat ([remote builder](docs/internal/remote-builder.md)).
- For hosts: Hewn sends `pause: true` with a build and takes a `{ "paused": "…" }` outcome ([remote builder](docs/internal/remote-builder.md)).
- For hosts: a retry (**Retry**, **Ask builder to fix**, or Hewn's own after a restart) sends `retryOf` to your builder's service, the first build of the chain it retries, the same on every retry of it, so you can count the chain as one build ([remote builder](docs/internal/remote-builder.md)).
- **Fixed:** a retry (**Retry**, **Ask builder to fix**, or Hewn's own after a restart) didn't give the builder the screenshots and files attached in the conversation; it does now, with the conversation, as the first try did.
- **Fixed:** a new tool you cancelled, or that failed, held on to its name: asking for it again said "capability '…' already exists". The new build now takes the name over. While one is being built (or waits to start), asking again says "already being built", and so does `hewn install` under that name, which ran alongside it before. The old build's **Retry** is refused while the new one is being built, works again if it fails or you cancel it, and says "created since" once it's live. A build that waited for the old one follows the new one when you retry it.
- **The intake suggests only connections Hewn can make.** A connection signs in with a key or token you paste, or a username and password (with a code if the service sends one); not OAuth, so not yet Google Calendar, Gmail, Spotify, Strava or Outlook. The intake no longer lists those as services to connect, and when you ask for one it says so and offers what works (a service with a key, an export to import, a calendar's secret iCal address). The docs, the builder's brief and the agents' tool description say the same; they named Google Calendar and Spotify as examples before. See [Connections](docs/connections.md).

## 0.4.9 (2026-10-28)

- **Share a tool as a file.** **Share…** (in the top bar of Info and of the open tool, or the tool's menu; connections too) shows what the file would hold before you download it: anything that looks personal or like a key, by file and line, partly hidden. One of your own stored keys in the code stops it (Share… lists each, and **Change…** asks the builder to take them out); your other settings found in it are flagged for you to look at. The file holds one version's code, tests, migrations, screens and sample data; Hewn never puts your data, keys, settings, conversations or logs in it. `hewn share <id>`. See [Sharing tools](docs/sharing.md).
- **Install a tool someone shared:** Settings › Data › **Install from a file**, or `⌘K`. Hewn reads it first; one sheet shows what it does, its **Source code**, what it will ask for (granted after install, as for any tool), its name ("Plant Log 2" if you have one) and **Start with sample data**. It installs through the same checks as a build, with no builder. A file Hewn can't trust is refused with the reason: over 5 MB, entries that overlap or repeat, npm code from outside the registry, or a format newer than this Hewn (it says to upgrade). Info shows where it came from, and Activity says "Installed from a file". `hewn install <file.hewn.zip>`.
- **Your builder reads a tool before you install it:** what it does with your data, what it keeps and where data goes, and what it found (warnings first: it says one thing and does another, asks for something it never uses, sends data somewhere the description doesn't say, its text tries to steer the reading), each with **Show** for the code at that line. Advice, not a gate: **Install anyway** skips it and stops it. The reading runs with no tools and no web: the tool's code is in the prompt, as data to review. A tool from the Hub ships with Hewn's reading and has **Check it yourself**; a file can't bring a reading of its own. The reading is kept with the install.
- **The Hub:** a new tab with tools ready to install, starting with Hewn's own (**Official**): Habits, Plant Log, Gift Ideas, Kid Quotes, Idea Tracker, Reading List and Running Log. They ship with Hewn, so the Hub works offline. Cards show what each needs and whether you have it; a tool's page has its screen (the tool as on a phone, with its widget; click to see it larger), Hewn's reading of its code, its operations and **Source code** (the same code browser as the install sheet; a version opens it too), and **Install** (or **Open** and **Install a copy** when you have it, under any name). A Hub tool's page and New have the normal top bar with **‹ Hub** or **‹ Home** where Hewn's name is. New offers it under the box (**Or start from** a tool in Hub, or a file someone shared), `⌘K` finds its tools last with **Install**, and a hosted Hewn's first run offers three of them. The npm package carries them in `dist/seeds/`.
- **Sample data:** made-up entries a tool starts with (`sample/calls.json`, calls to its operations). Sharing needs it. Builders write it when they create a tool; **Ask builder** in Share… adds it to an older one, or **Write it yourself** (with the format and each operation's fields beside it). A connection shares without it. A version whose sample data doesn't run on an empty tool isn't promoted.
- **Start over:** Info › Data empties a tool's data and keeps the tool (type its id; a copy of its data is kept aside first), with its sample data again if you like. `hewn data reset <id>`.
- **npm gets registry versions and no settings from a tool:** a build whose `package.json` or lockfile asks npm for a path, a link, git or a URL, or that carries an `.npmrc`, fails, saying which dependency (or file) to change. npm runs on the machine itself, outside the builder's sandbox, so a tool could otherwise have it clone with your keys or run a program of its choosing.
- **A tool's code imports only its own files** and its npm dependencies: an import of a file elsewhere on the machine (a path, `../` out of the tool, a link) or with an import attribute other than `type: "json"` fails the build, saying which.
- **Info is one page you act on.** Each part of a tool is a section with its actions right there: **Operations** with **Run** (the first five, then **Show all**); **Allowed to** with **Authorize** and **Deny** for what it asks, **Revoke** for what it has, and the model: a tier or one specific model from its menu, this month's spend, and its own monthly cap; **Data** with how many rows it keeps, when it last wrote, **Export** and **Start over**; **Schedules** with a switch each, **+ Add schedule**, and **Try again** on a failed run; the **Widgets** themselves at the size they're meant for (**S M L** shows the others) with **Add to Home**; **Instructions** with **Remove** and a line to add one; the last two **Versions**. Every section shows, empty or not. What needs you (something to authorize, a failed change, a model to set up, a paused schedule) sits above **Change it** with its one button. Two columns in a wide window. A connection's page uses the same sections.
- **Deny means no.** Saying no to something a tool asks for is kept (it was only hidden in that browser): nothing asks for it again, on Home, in the Inbox or through an agent's access request, until the tool's next version (a quick change, such as another model tier, keeps it), and agents are told you said no once that's all it lacks. You say no to a host, another tool or a model; a secret is set or not. The tool still can't run without it, so Info offers **Ask builder to work without it**, or **Authorize** after all. Leaving a switch off in the authorize sheet says no too. From the terminal: `hewn grants deny <id> <grant>`.
- **Versions are pages.** **All versions** lists them; a version's page has Info's top bar, the tool (back to its Info) above a menu of its conversation, spec and builder's log (as Settings has), each in a panel, and **Continue from here** and **Restore…** (it asks first) by its title. **Versions** in a tool's menu opens the list (it was a dialog).
- **See a tool's code:** a version's **Files** lists what changed since the version it was built on (the one before, or the one you restored), with each file as a git-style diff (both line numbers, added and removed lines tinted), or every file as it is (**Source**), in syntax colours; JSON written compactly is laid out (**Pretty**, or **As written**); the first 5,000 lines of a file show. For hosts: `GET /api/capabilities/:id/code?version=N[&path=…]` (owner only).
- **Build screenshots show the tool in use.** With sample data, a build's screen is checked twice, empty and filled with it, and the screenshot you see is the filled one; changed widgets are drawn with what they'd show filled too. A screen that breaks only once there's data fails the build, and the build page shows it as it broke (any failed render shows its screenshot now).
- **Try again on a schedule's failed run** runs it once now, as the schedule does, to see whether it was a passing problem or a fix worked. A success clears its failures; one paused after failing stays paused until you switch it on.
- **Pages change in one step:** the page on screen stays until the next one is ready (up to 0.6 s, with a thin bar moving along the top; then its loading state), instead of a skeleton flashing in between and the page building downwards. A slow page you've already left no longer draws over the one you went to, and Home redrawing itself keeps its grid on screen.
- **Info's top bar has Change…** next to •••, as a connection's page does.
- **The change drawer's width drags** by the handle on its left edge (no narrower than its box needs), and stays as you left it. **Continue** on the last conversation lands at the box, however long the conversation.
- **The authorize sheet's button says Deny** when every switch is off.
- **Changing a tool's model tier waits until the new version is live,** so Info shows the new tier (it showed the old one until a reload).
- **Delete asks you to type the tool's id,** as Start over does.
- **Got what you asked for?** is a quiet strip at the foot of the tool instead of a toast.
- **The box:** attached files and images are 64px tiles with their name and ×, and open when clicked; **Draft now** is a link; the model menu says who builds and on what ("Claude Code · Fable · high"); a rule the intake saved is one line, "Saved as a rule: …", with Undo.
- **Set icon** shows the icon at the three sizes it's seen at, centres the 5×5 grid with a count of lit cells, and gives Colour and Saturation the same width.
- A change waiting for the one before it says so the same way in the change panel, the Inbox and Activity: "waiting for the change before it".
- **The tool spec is ABI 2.5** (`@hewntools/spec` 2.5.0): the manifest's `source` (where an installed tool came from; Hewn writes it and replaces a builder's), `hub` and `minVersion` on `requires.capabilities` for tools that will build on others from the hub (Hewn's to write too), and `sample/calls.json`. A tool installed from a file declares at least 2.5, so an older Hewn refuses it with the reason.
- Docs: [Sharing tools](docs/sharing.md) is new; concepts, your data (Export or Share…), the web client, building tools, the threat model and the internal architecture and security notes cover sharing and the Hub.
- For hosts: `GET /api/capabilities/:id/data` (owner only) gives a tool's rows per table, counted without reading them, and its last write in its latest 500 calls (`callsChecked` says how many there were); the runtime port gains `countState`. `POST /api/schedules/:id/run` runs a schedule once now. The intake has a third mode, `summarize`, with a `summary` reply (run it without web tools); Hewn now gives Claude Code, Codex and OpenCode the intake's prompt on stdin.
- **Fixed:** `hewn serve` that can't start workerd (its port taken, say) stops with "workerd did not start" instead of staying up without it, restarting workerd every 30 seconds. Hewn stopped hard while starting no longer leaves a half-written `format.json` that kept it from starting again ("Unexpected end of JSON input"), and the CLI never reads a half-written `supervisor.json`.

## 0.4.8 (2026-10-24)

- **Changes to one tool take turns.** A second change asked for while one builds (by you or an agent) waits for it, then starts from the version it leaves, whether that one went live or failed. It used to run alongside and fail at the end with "capability changed since this build started", after a full build. The build page and Activity say "Waiting for the change before it"; for agents, the build has `queued: true`. An agent's change waiting for your approval doesn't hold the next one up. The box and agents see the changes on their way (for agents, `changesComing` in `capabilities_get`), so the next one builds on them. Deleting a widget or changing a tool's model, which make a version at once, wait until a change on its way is done.
- **Saturation for tool icons,** next to the colour in **Set icon…**: 0 to 150%, 100 by default. Below 25% the glyph turns black or white, so 0 suits a black-and-white brand (Ghost, the BBC). Builders can set it too: `saturation` in `capability.json`, ABI 2.4 (`@hewntools/spec` 2.4.0); the builder brief says when. The agents and model providers with black-and-white logos (ChatGPT, Codex, OpenCode, Cursor, Copilot, OpenAI, OpenRouter) now have grey tiles instead of a colour picked for them, and so do Hewn's own actions and pages in the ⌘K palette and Agents › Add… (colour is for tools; Add… has the palette's pixel glyphs instead of arrows). The slider marks 100%, and **Use default** shows the default until you save. Set icon… saves only what you changed, so a builder's later colour still shows where you left it alone.
- **"Keep talking" greys out the proposal's Build button,** so it's clear the next reply brings a new proposal (or **Draft now** does).
- **Dragging a slider out of a dialog no longer closes it** when you let go outside (Safari).
- **Ask the box how Hewn works.** A question in the box where you describe a tool ("can a tool read my calendar?", "how do I undo a change?") gets an answer from Hewn's docs instead of a proposal, and it says when the docs don't cover it. Reply to carry on ("ok, draft one"). It sticks to Hewn: trivia, or something Hewn doesn't build (a Claude skill), gets a line saying so, and a tool if one would do. For hosts: the intake's reply may be kind `answer`.
- **The box's replies show bold, lists and code** instead of the raw Markdown (`**`, `- `, backticks).
- **Agents can read Hewn's docs:** a new MCP tool, `hewn_docs`, every agent has, whatever its scopes. It lists the pages (the user docs and the tool and agent spec), searches them, or reads a page or one section, so an agent you ask how something in Hewn works answers from the docs instead of guessing. The npm package now ships the docs for it (`dist/docs/`).

## 0.4.7 (2026-10-24)

- **OpenCode builds tools, talks them through, and uses them.** Pick it under Settings › AI › Builds tools (or on the first run), on any provider it's signed in to (`opencode auth login`), on its free tier, or on a local model server from your `~/.config/opencode/opencode.json` (Ollama, LM Studio): Hewn lets the build reach that server's port and nothing else on your machine. Its models are listed as `provider/model`, with the model's own reasoning levels as efforts. It builds like the others: in a sandbox, in a home of its own (your provider logins for the run, never your config, plugins, sessions or MCP tokens), with file tools only, and a failed validation resumes its session. Connect it as an agent from Agents › Add… or `hewn setup --agents opencode`: Hewn registers itself in OpenCode's global config and `AGENTS.md`, then `opencode mcp auth hewn` signs it in. `hewn doctor` checks it. If it had no `~/.config/opencode/AGENTS.md`, it now reads that instead of `~/.claude/CLAUDE.md`.
- A build on a model OpenCode doesn't list stops at once ("… isn't available"), and a run that never says anything is stopped after three minutes instead of the full fifteen: OpenCode 1.18.18 hangs rather than fails on a model it can't resolve.
- **When an agent won't run the model you picked, the message says why,** in the agent's words ("opencode/deepseek-v4-flash-free isn't available (Upstream request failed: Model is unavailable)"), and the model lists mark a model that failed in the last hour: OpenCode's free tier changes which models it serves, and its list can lag behind.
- **One retry at a time.** A failed build that was retried already (by you, or by Hewn after a restart) can't be retried again; the answer names the retry to wait for. An agent that checked on an old build after a restart used to start a second build of the same request next to the first.
- Starting an OpenCode build no longer pauses Hewn while its plugin SDK is copied into the build's home (cloned, off the main thread; `opencode models` and `opencode debug config` are asked the same way), and the watchdog pings twice before calling workerd stuck, so a pause on Hewn's own side doesn't restart it under a running build. The build page's clock runs from the first attempt instead of starting over on a retry.
- Settings › AI › Builds tools › Model… reads the agent's list afresh each time it opens (a provider you just signed in to shows at once), shows Effort only for a model with levels, and no longer says "stays on this one" under each pinned model. Clicking a disabled control in a sheet no longer closes it. The "OpenCode is connected" sheet doesn't offer "Build tools" when OpenCode already does that. `hewn uninstall` takes Hewn out of OpenCode's config and MCP logins itself (plain JSON; a `.jsonc` with comments is listed for you).
- `hewn doctor`'s "Builds tools" line names the agent ("Claude Code isn't logged in") and gives its own install or sign-in step ("run codex login", OpenCode's install line) instead of a generic one.
- Review fixes before the merge: provider keys from your environment (OpenRouter, Gemini, Groq…) reach only the OpenCode run, not Claude Code's or Codex's; your OpenCode directories stay closed to builders when the XDG variables move them; the run's copy of your provider config goes when the run ends, as its login copy does; the model check runs from the run's own home, not the workspace; a reasoning level OpenCode names in a way Hewn can't pass isn't offered; each intake gets an OpenCode home of its own.

## 0.4.6 (2026-10-22)

- **A build keeps what led to it,** for the tool's life: your conversation with the intake, the spec, and the builder's log (which used to go after 30 days). The build page has **Conversation** next to **Spec agreed**; in **Versions**, each version's **Details** opens its conversation, spec and log, and **Continue from here** starts a change with that conversation as context. Builds also record which brief they ran on.
- **Instructions for building:** standing rules the builder follows on every build, for every tool (Settings › AI › Instructions for building) or for one tool (Info › Instructions). Tell the intake a rule ("always Swedish copy", "keep this one to a single screen") and it remembers it: the chat shows what was saved, with Undo. One rule per line, yours to edit. Each build records the instructions it ran with.
- **The intake asks until it's clear.** A one-line idea gets questions before a proposal, each with the default it would assume ("I'd assume one entry per day; right?"), so "go ahead" answers them all; a specific change ("show pace per km in the table") still gets a proposal at once, a vague one ("improve the UX") gets asked what bothers you. No more cap of three rounds: **Draft now** in the box skips the rest and takes its assumptions, listed with the proposal.
- **Paste a screenshot, drop a file, or Attach.** Images (resized before they go up; up to 5 per message) and text files (up to 256 KB) go with your message to the intake, and with the build to the builder, in its workspace under `attachments/`, listed in the request. They stay with the build like the conversation, and show in it. A tool's own top-level `attachments/` folder is reserved for them from now on (workspace only, never part of a version). For hosts: `attachments` on `/v1/intake`.
- **A failed validation no longer starts the builder over.** The next attempt resumes the first one's session with the failure (Claude Code and Codex), so it fixes the candidate instead of re-reading the brief and rewriting it: a second attempt takes a fraction of the first. The host's builder gets a `session` per build to do the same. Claude Code builds and the Claude Code intake also run `--restricted` (no code-running tools), each build's builder session lives in a home of its own (no other build can read it), and every workspace gets an `AGENTS.md` pointing at the brief, for builders that read it on their own. The brief asks for icons centred in their 5×5 grid. The builder brief is `@hewntools/spec` 2.3.3.
- **Got what you asked for?** When you next open a tool after a build went live, a note at the bottom asks once per version (within a week of the build): Yes, Not quite (which opens the change panel), or skip. The answer stays in your Hewn; nothing is sent anywhere. `hewn feedback` lists recent builds with what they ran on, attempts, your answers and what the record shows (a failed build whose retry went live, another change within a day, a restore within a week, the tool deleted within a day).
- **Fixed: `hewn models <subcommand>` from the terminal.** It skipped the word after `models`, so `hewn models key anthropic` (and `use`, `tier`, `cap`, `price`, `set`, `list`, `check`) failed with "unknown: hewn models anthropic". Settings › AI › Models was unaffected.
- **The intake gets 15 minutes, not 5,** so a long brief on a slow, careful model (Opus at high effort) finishes. Past that it's stopped with "intake took longer than 15 minutes, so Hewn stopped it" instead of the last raw line of its output.
- **Fixed: a tool's hidden message showed as an empty red box.** The UI kit's `.notice` (and any other class that sets `display`) no longer overrides `hidden`.
- **The chat box's example goes after your first message** (no "Track my coffee beans…" under a conversation about something else).

## 0.4.4 (2026-10-20)

- **For hosts: hosted mode** (`HEWN_HOSTED=1`, with `HEWN_BUILD_URL`; optional `HEWN_HOST_SIGNIN_URL`). For an owner who has no terminal: signed-out pages and agent approval send them to the host's sign-in instead of a command, the first run goes straight to making something (no "who builds" step), and Settings hides what the host manages. See [remote access](docs/remote-access.md#running-hewn-for-someone-else-hewn_hosted).

## 0.4.0 (2026-10-19)

The first public release. What's in it:

- **Tools of your own.** Each has typed, versioned operations, its own SQLite database, tests, and optionally its own screen and widgets. Every change is a new version, tested on a copy of your data before it goes live; restore an earlier one any time.
- **Built by your coding agent.** Describe a tool; the intake (Claude Code or Codex on your machine) asks what it needs to know and proposes it, and the builder writes it in a sandbox. A failed build says why and can be fixed with one click.
- **Every agent.** Claude Code, Codex, claude.ai, ChatGPT and any MCP client connect over OAuth. You approve each one and choose what it may do (see, use, make, change; all tools or some). Destructive calls wait for you. Widgets show right in the chat in clients that support MCP Apps.
- **Connections** to the services you use, holding their keys encrypted where no tool or agent can see them, with health checks and sign-in flows.
- **Models for tools that think,** with your own Anthropic, OpenAI or OpenRouter key, four tiers, and a monthly budget.
- **Schedules** in your time zone; agents can only propose them.
- **The web client:** Home with widgets, the Inbox for what needs you, Activity, a command palette, Settings, and a phone layout. Use it from anywhere with a public URL and passkeys.
- **Behind a proxy:** with `HEWN_PROXY_SECRET`, the public listener answers only requests that carry it ([remote access](docs/remote-access.md)).
- **Your data stays yours:** local first, nightly backups, export, and a threat model that says what's protected and what isn't.
- **Install** with `curl -fsSL https://hewn.tools/install.sh | sh` or `npm install -g @hewntools/cli`, on macOS, Linux and Windows (WSL). ABI 2.3.
